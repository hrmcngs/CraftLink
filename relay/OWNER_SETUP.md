# hrmcngs専用の主催者登録

中継の主催者接続（`/_bridge`）は、従来の `CRAFTLINK_RELAY_SECRET` に加え、登録した hrmcngs のMacのEd25519署名を要求します。招待されたスマホの参加方法は同じです。名前だけを名乗る接続・登録されていない鍵・期限切れ署名・署名の再利用は拒否します。公開鍵が未設定なら中継は起動しません。

1. Macで hrmcngs として `sh run.sh --offline --login` を一度タイトル画面まで起動します。
2. `node relay/owner-auth.mjs --setup` を実行します。秘密鍵を `.craftlink/owner-key.pem`（権限600）へ保存し、公開鍵だけを表示します。再実行しても既存の秘密鍵を変更しません。
3. Renderの該当サービスのEnvironmentで `CRAFTLINK_OWNER_PUBLIC_KEY` に、表示された公開鍵を登録します。既存の `CRAFTLINK_RELAY_SECRET` も維持します。
4. この変更をRenderへデプロイしてから、Macで `sh school.sh --mods` を実行します。

秘密鍵と認証キーは共有しないでください。`.craftlink/` はGitや配布ZIPに含めません。公開鍵の登録・デプロイが完了するまで公開サービスの制限は変更されません。

起動状態はVS Codeの **⌘ShiftB**、または `sh menu.sh` の **3 → 1** で選べます。`--dev` は同じWi-Fi・LAN専用ゲストで、学校用中継には使えません。`--login` はMicrosoft認証、`--cached-login` は保存済みの名前・UUIDによるローカル起動です。初回の主催者登録には手順1の `--login` が必要です。学校用起動では中継の主催者登録・署名が必要です。

この方式が中継側で証明するのは、管理者がhrmcngs用として登録したMacの秘密鍵を持つことです。毎回Microsoftに照会して現在のアカウントを証明する仕組みではありません。学校ではMicrosoftへの再認証なしで署名できます。Renderの登録権限を持つ本人が初回登録してください。Macを交換したときや秘密鍵を失ったときは、別の鍵を生成してRenderの公開鍵を更新します。

通常起動・学校用起動のログイン状態は別々に保持します。一度 `sh school.sh --cached-login` または `sh school.sh --login` で選ぶと、次から `sh school.sh` だけで同じ状態を使います。学校で認証APIへ接続できない場合は `sh school.sh --cached-login` を選んでください。保存する選択は `.craftlink/login-school`（通常は `login-run`）で、認証トークンはここには保存しません。Microsoftログインの期限切れ・失効時は再認証が必要です。Minecraft Education版に対応する変更ではありません。

## HTTP 403で起動できない場合

MinecraftのMicrosoftログインとは別の、中継の主催者認証で拒否されています。401・403では自動再接続を停止してメニューへ戻ります。公開側の403応答から、どの認証条件で拒否されたかは断定できません。

1. メニューの **3 → 5**（または `sh craftlink owner`）で、このMacの公開鍵を表示します。既存の秘密鍵は作り直しません。
2. RenderのEnvironmentの `CRAFTLINK_OWNER_PUBLIC_KEY` が表示された公開鍵と同じか確認し、変更した場合は保存・再デプロイします。
3. 中継キーが異なる場合は、メニューの **3 → 6** でRenderの `CRAFTLINK_RELAY_SECRET` を非表示入力します。秘密キーはチャットへ送らないでください。
4. 同じ中継へ接続中の別ターミナル・別Macがあれば終了します。Macの日時が自動設定になっているかも確認します（署名の許容時刻差は60秒）。
5. 最初の画面の **1** で再度起動します。

通常の同じWi-Fi接続は、メニューの **2 → 2 → 1** で起動できます。これは離れたWi-Fiやモバイル通信からの接続には使えません。

### 原因を個別表示する診断

新しい中継は、拒否応答にキー不一致・署名拒否・接続済みの区別を含めます。Mac側は「原因: …」と表示します。署名拒否の場合は、正しい中継キーを持つ接続にだけ公開鍵の指紋を返し、このMacの鍵との不一致も判定します。秘密キー・認証トークン・秘密鍵は応答へ含めません。

「中継が詳細診断に未対応」と出る場合は、Renderの **Manual Deploy → Deploy latest commit** で最新コードを反映してください。デプロイだけで登録キーの不一致が修復されるわけではありません。反映後の「原因: …」に従って必要な設定だけを変更します。
