# CraftLink

**Minecraft Java Edition 1.20.1 / Forge 47.4.10以上（47系） / Java 17** 用のクライアントMOD。
スマートフォンのブラウザをタッチコントローラーとして使います。LAN・USB接続では外部サービス不要です。離れたWi-Fi・モバイル通信には、任意でHTTPS中継を利用できます。スマホアプリ、サーバー側MODは不要です。

## 導入・接続

1. Forge 1.20.1をインストールします（開発・検証対象は47.4.10）。
2. `craftlink-forge-1.20.1-0.1.0.jar` をMinecraftの `mods` に配置します。`-thin.jar` は配布用ではありません。
3. Minecraftを起動し、ワールドまたはマルチプレイヤーサーバーに入ります。
4. **F8** →「接続を開始」。キーはMinecraftの「操作設定」で変更できます。
5. PCに到達できるLANのスマホでQRを読み取り、ブラウザで開きます（PCは有線LANでも可）。USB接続は下記の手順を使用します。
6. Minecraftで「接続を許可して戻る」を押します。横向きで操作してください。
7. 終了時はスマホの「切断」、またはF8画面の「端末を切断」「停止」を使います。

PCのファイアウォールに確認された場合、プライベートLANに限りTCP 8765を許可します。
初回ビルド・Minecraft導入後のLAN・USB接続にはインターネット接続は不要です。HTTPS中継ではMac・スマホ双方にインターネット接続が必要です。

## ユーザーごとのWebリンク・QR

各ユーザーが自分のMinecraftで「接続を開始」を押すと、そのMinecraftに接続する専用Web URLとQRを自動生成します。
F8画面のタイトルには操作先のMinecraftユーザー名を表示します。
URLは固定の共通URLではなく、PCの接続先アドレス・ポート・ランダムな一時セッショントークンから生成します。
別ユーザーのMinecraftや別の起動セッションとはトークンを共有しません。Webサーバーを別途公開する必要はありません。

- 「URLをコピー」で、QRと同じ専用Webリンクをコピーできます。
- 「QR再発行」で接続中の端末を切断し、古いURLを無効にして新しいURL・QRを生成できます。ポートや接続先はそのままです。
- 接続先IPを切り替えた場合もQRは自動更新します（同じセッションのトークンを維持）。
- 有効期限は30分。期限切れ後は「QR再発行」、または停止・再開始で更新できます。

ここでの「ユーザーごと」は **各Minecraftクライアントの接続セッションごと** です。
ユーザー名を知っているだけでは接続できず、トークンとPC側の承認が必要です。恒久的なアカウント用URLやオンラインログインサービスではありません。
同じPCで複数のMinecraftを同時に動かす場合は、各インスタンスの設定で異なるポートを指定します。
QR自体は接続経路を作りません。LANではPCへ到達できるネットワーク、Android USBではADB転送が必要です。

## USBケーブルで接続（同じWi-Fiは不要）

### Android：ADB USB転送

スマホ用アプリは不要ですが、PCに [Android SDK Platform-Tools（adb）](https://developer.android.com/tools/releases/platform-tools) が必要です。
スマホで「開発者向けオプション」→「USBデバッグ」を有効にし、データ通信対応ケーブルでPCへ接続して、このPCを許可します。

1. PCのシェルで `bash scripts/android-usb.sh` を実行します。標準ポート8765をUSB経由でPCへ転送します。
2. MinecraftでF8 →「接続を開始」。
3. 下部の「接続先」を押して **127.0.0.1** を選びます。
4. そのQRをAndroidで読み取り、Chromeで開きます。スマホのlocalhostがUSB経由でPCへ転送されます。
5. PCで「接続を許可して戻る」。Wi-Fiを共有する必要はありません。
6. 終了時に切断し、PCで `adb -d reverse --remove tcp:8765` を実行します。

別ポートなら `bash scripts/android-usb.sh 9876` とMOD側の `port = 9876` を一致させてください。
スクリプトはUSB端末が複数ある場合に勝手に1台を選びません。対象以外を外すか、
`adb -s SERIAL reverse tcp:8765 tcp:8765` を明示的に実行してください。
ケーブルの抜き差し・端末再起動後は転送を再設定します。デバッグ許可は利用後に無効化できます。
この方式は [Android公式のadb reverse](https://developer.android.com/develop/ui/views/layout/webapps/access-local-server) に基づきます。

### iPhone：USBインターネット共有

iOSにはAndroidのADB転送がありません。ケーブルを挿すだけでSafariからPCのHTTPサーバーへ接続できる機能は、このMODでは提供しません。
代替は [Apple公式のUSBインターネット共有](https://support.apple.com/en-ie/111785) で作るローカルネットワークです。

1. iPhoneのインターネット共有を有効にし、USB接続してPCを信頼します。WindowsではApple DevicesまたはiTunesが必要です。
2. PCのネットワーク設定で、iPhone USB側に割り当てられた **PCのIPv4アドレス** を確認します。
3. CraftLinkを開始し、「接続先」でそのアドレスを選び、QRをiPhoneのSafariで開きます。
4. 一覧にない場合は `advertisedHost` にそのPC側アドレスを設定し、停止・再開始します。

Appleの手順はUSBネットワーク作成までのものです。iPhone側からPCへのHTTP接続の到達性はOS・ドライバー・ファイアウォール等に依存し、
**この経路の実機検証は未実施**です。USB共有が使えない端末・契約ではLAN接続を使用してください。

## 離れたWi-Fi・モバイル通信から接続（HTTPS中継）

通常操作・NPC参加モードの両方に対応します。Cloudflareを経由するため、Mac・スマホ双方のインターネット接続が必要です。ルーターのポート転送は不要です。

1. Macに一度だけ `brew install cloudflared` で中継ツールを導入します。[公式ダウンロード手順](https://developers.cloudflare.com/tunnel/downloads/)。
2. `sh run.sh` または `sh menu.sh` からMinecraftを起動します。
3. 別のターミナルで `sh menu.sh` の **8** を選び、通常操作かNPC参加を選択します。直接起動する場合は以下を使います。

   ```sh
   sh tunnel.sh controller  # 通常操作、ポート8765
   sh tunnel.sh classroom   # NPC参加、ポート8766
   ```

4. 表示された `https://……trycloudflare.com` をコピーします。MinecraftのF8画面の「別のWi-Fi」、NPC参加なら「みんなで参加」内の「別のWi-Fi」に貼り付けて保存します。接続が開始済みなら先に停止してください。
5. Minecraftで接続を開始し、新しいQRをスマホで読みます。PCで接続を許可すると操作できます。スマホは別のWi-Fi・モバイル通信でも構いません。

中継ターミナルは開いたままにします。Ctrl+Cで中継を停止できます。再起動するとURLが変わるので、接続を停止して新しいURLを保存してください。サーバー開始前に中継URLを開くと一時的に接続エラーになります。

設定するのはHTTPSのルートURLのみです。`/classroom.html` やトークンはMODが付けます。通常用の `externalUrl` と参加用の `classroomExternalUrl` は別設定です。独自ポートなら `sh tunnel.sh classroom --port 9000` のようにMinecraft側のポートと合わせます。

HTTPS中継を設定すると、MODの待ち受けは強制的に `127.0.0.1` となり、指定したHTTPS Originからの操作だけ受け付けます。ブラウザとの通信はHTTPS / WSSです。LANへ戻すには接続を停止し、「別のWi-Fi」→「LAN接続に戻す」を選びます。MODが中継を自動公開することはありません。

Quick Tunnelは試用・開発向けで、稼働保証はありません。[Cloudflare公式説明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)。学校など中継サービスへの通信が制限されるネットワークでは接続できない場合があります。通常操作の映像配信は通信量を消費し、遅延は回線次第です。

**NPC参加モードは先生のPC画面を共有して見る方式で、スマホへの映像配信はありません。** 遠隔地からNPCを動かす場合、先生の画面を別途共有する必要があります。通常操作モードには映像配信があります。

ローカルHTTPSプロキシ経由で実JavaサーバーへのWSS接続・承認・入力解除を検証済みです。実際のCloudflare中継とスマホのモバイル回線での実機検証は未実施です。

### 有線LAN・別のWi-Fi

PCが有線LAN、スマホがWi-Fiでも、相互に通信できる同じルーター配下なら使えます。
離れたWi-Fiや外出先からは、下記のHTTPS中継、または既存のプライベートVPNでPCへ到達できる経路を使用します。
VPNのPC側IPを「接続先」で選ぶか `advertisedHost` に設定します。仮想インターフェースと100.64.0.0/10のアドレスも候補に含めます。
VPNの構築やインターネットへのポート公開はMODが自動実行するものではありません。

## 携帯コントローラーの操作設定

Minecraftの **設定 → 操作設定 → 携帯コントローラー設定…** から開きます。
標準のMinecraftボタン・スライダー・背景を使用し、キーボード操作や読み上げも標準ウィジェットに従います。

- 映像を直接タップするジョイスティック方式（標準）・方向ボタン方式と、照準＋専用アクションボタン方式を切り替えられます。
- 視点感度とボタンサイズ（80〜140%）を設定できます。
- 「携帯端末を接続…」からQR接続画面へ進めます。
- PCで変更した設定は承認時と変更時に接続中のスマホへ反映します。PCのキー割り当ては変更しません。

スマホの「操作設定」からも同じ項目を調整できます。設定を開く・操作方式を変更する・画面を回転する際は入力を解除します。
スマホ側の設定はその端末に保存しますが、接続し直すとPC側の設定が優先されます。
ジョイスティックは8方向の移動意図として送信します（歩行速度を変えるアナログ入力ではありません）。
統合版の公式UI・操作実装そのものではなく、Java Editionの通常ルールで動く携帯版風レイアウトです。

## 操作

| スマホの操作 | Minecraft |
|---|---|
| 左側のジョイスティック / 方向ボタン（同時押し可） | 前進・後退・左右移動 |
| 右側の空き領域をスワイプ | 視点。「操作設定」の感度スライダーで調整 |
| ジャンプ | 押している間有効 |
| スニーク・ダッシュ | タップで切り替え（従来の方向ボタン方式は長押し） |
| 攻撃 / 掘る | 左クリック、長押しでブロック破壊 |
| 使う / 置く | 右クリック、長押しで継続使用 |
| 持ち物 | インベントリを開く |
| 1〜9 | ホットバーのスロット選択。750ms長押しで1個捨てる |
| 捨てる・オフハンド | 1アイテムを捨てる・両手の交換（押下時に1回） |
| ESC | Minecraftのポーズメニューを開く |

移動・視点・アクションを別々の指で同時操作できます。
スマホのバックグラウンド移行時は入力を解除します。

### 映像と直接タップ

PCの接続承認後、スマホにMinecraftの映像を配信します。映像上をタップすると、その位置のブロックを使用・設置、またはエンティティを攻撃します。350msの長押しで採掘、指を動かすと視点移動に切り替わります。操作対象はJava Editionの通常の到達距離・ゲームルールに従います。

ゲーム内GUIでは表示位置に対応するクリック・ドラッグ・スクロールを送ります。「戻る」でGUIを閉じられます。文字入力にはPCを使用してください。PCとスマホの操作設定で映像の許可・受信を停止できます。

映像は最大854×480、15fpsのJPEGで、音声は含みません。受信確認ごとに次のフレームを送り、遅い回線で映像を溜めません。古い映像に対するタップを拒否します。ワールドの直接タップは一人称視点で使用してください。統合版と同じ滑らかさ・全操作の再現を保証するものではありません。

軽量化として、JPEG変換用の画像・出力バッファを再利用し、一時ファイルを作らずメモリ上で変換します。
画素が変わらない映像は約500msごとの更新に抑えます（画素比較用のGPU読み戻しは継続）。変化する映像は最大15fpsです。
同じ操作状態の再送は約250ms間隔に減らし、押下・解除・視点移動・スロット選択はその都度送ります。
スマホのタブがバックグラウンドに移った際は入力を解除して映像転送を停止し、復帰時に再開します。

参考測定: Apple M2 / JDK 17で854×480の合成画像を20回ウォームアップ後、60回JPEG変換したところ、
旧実装の8.08ms・8.41MiB割り当て/フレームに対し、バッファ再利用版は4.06ms・5.16MiBでした。
JPEGはどちらも127,572バイトです。これは単独の変換処理の測定で、ゲーム全体のFPSや実機での速度改善を保証する値ではありません。

操作方式は[Minecraft公式の操作説明](https://www.minecraft.net/ja-jp/article/minecraft-controls)と[Bedrock 1.19.50のタッチ操作更新](https://www.minecraft.net/en-us/article/1-19-50-update-available-bedrock)を参考にしています。

## 学校向け「みんなで参加」モード（Mac 1台）

Minecraft Java Edition 1.20.1 / Forgeを起動したMac 1台と、最大8台のスマホで参加できます。
各スマホは、先生のシングルプレイワールド内にいる別々のNPCを操作します。Minecraftの起動は1つで、専用サーバーの別起動は不要です。
NPCはプレイヤーと同じ形・大きさの専用人型エンティティです。参加番号ごとに8種類のバニラ標準スキンと色付きの名前で識別できます。実際のログインプレイヤーや、自動で課題をこなすAIボットではありません。
歩行・走行時の手足、待機時の腕、しゃがみ姿勢、顔の向き、挨拶ボタンの腕振りにバニラのプレイヤーモデルのアニメーションを使います。ジャンプは通常の重力・移動で表現します。
外部スキンサーバーや追加のアニメーションライブラリは不要です。個別スキンのアップロード、エモート、他MOD独自のプレイヤーアニメーションとの連携は未実装です。

1. Macで通常起動（`sh menu.sh`の2番、または`sh run.sh`）し、シングルプレイのワールドで平坦な広場に立ちます。
2. F8 → **みんなで参加 → 受付を開始** を押します（通常のコントローラー接続とは別です）。
3. 同じLAN上、またはHTTPS中継を設定したスマホで共通のQRを読みます。
4. 先生が各端末の番号を確認して、PCで個別に **許可** します。
5. **開始 / 再開** を押すと、各スマホから自分の番号のNPCを操作できます。
6. **F9** または参加画面の **全員停止** で全員を停止。**部屋を終了** で端末を切断しNPCを削除します。

スマホは「前後左右・ジャンプ・はやく・ゆっくり・あいさつ」と、スワイプによる向き変更に対応します。
参加モードでは、**先生のMac画面をみんなで見ながら操作します**。端末ごとの一人称映像や映像配信はありません。
採掘・設置・攻撃・インベントリ操作・追加MOD操作は提供しません。通常の1台用コントローラーには従来の機能が残ります。
圧力板など、NPCの接触による通常のワールド反応は起こり得ます。NPCは受け付け開始時の地点から約32ブロック以内で動き、範囲外や落下時は開始地点付近に戻ります。

参加用のポートは標準 `8766`（設定 `classroomPort`）。通常のコントローラーは `8765` です。
参加モードはシングルプレイ専用で、通常のマルチプレイヤーサーバーへのNPC追加には対応しません。
部屋の有効期限は30分。端末ごとに独立した再接続トークンを持ち、切断後30秒以内の再接続では同じNPCを引き継ぎます。
30秒を過ぎた再接続は新規参加となり、先生の許可がもう一度必要です。
通信が750ms途絶えると入力を解除し、切断したNPCも停止します。ワールド終了・次元移動で部屋を終了し、NPCはワールド保存に含めません。
参加中はフォーカス喪失による自動ポーズを一時的に無効にし、部屋終了時に元へ戻します。ESCによる通常のポーズとは別です。

学校のWi-Fiが端末同士の通信を禁止している場合、LAN接続は使えません。HTTPS中継を許可するネットワークなら上記の中継方式を利用できます。
LAN方式ではインターネット接続は不要ですが、端末間のネットワーク接続は必要です。HTTPS中継にはインターネット接続が必要です。複数台のUSB接続はこの参加モードの対象外です。
F8/F9はMinecraftのキー設定から変更できます。MacではFnキーの併用が必要な場合があります。

## 他のMODの操作を追加する

PCの **設定 → 操作設定 → 携帯コントローラー設定 → MODの追加操作…** を開き、スマホに追加したい操作をONにします。
導入済みMODのキー割り当てと、CraftLinkの登録APIで提供された操作が候補になります。最大16個、初期状態ではすべてOFFです。
接続中のスマホに「MOD操作」が表示され、開くと選択したボタンをタップ・長押しできます。
この選択画面の設定変更はPCで行います（映像経由のタップは受け付けません）。設定は `config/craftlink-client.toml` の `addonActions` に保存されます。

キー連携は既存のキー状態・クリック数を変更せず、選択したMODキーの `isDown()` / `consumeClick()` の読み取りに独立した入力を合成します。
通常のPC操作を保持し、Forgeのキー競合コンテキストを尊重します。MODがGLFWの生入力・独自のキー処理・別のGUI入力を読む場合は対応できません。
キー修飾子の物理押下は再現しません。ボタンは対象キー割り当ての操作自体を呼び出します。
すべてのMODへの互換性や、各MODのネットワーク処理の正しさを保証するものではありません。
連携方式の参考: [Forge公式のキー割り当て説明](https://docs.minecraftforge.net/en/1.20.x/misc/keymappings/)。

### MOD開発者向け登録API

CraftLinkをクライアント側の依存として使用し、クライアント初期化時に一度だけ登録します。

```java
import dev.craftlink.addon.AddonActions;

AddonActions.register("example:ability", "特殊能力", down -> {
    // Minecraftのメインスレッドで呼ばれる。短押しでもtrue→falseを通知。
    if (down) {
        // 自分のMODのクライアント操作APIを呼ぶ。
    } else {
        // 長押し操作の終了・解除。
    }
});
```

登録だけではスマホから実行できません。PCで選択すると `addon:example:ability` が許可されます。
GUI表示・切断・750msの入力タイムアウト・選択解除・Minecraft終了で解除を通知します。
コールバックは短時間で処理し、自分のMODのゲームルール・通常のサーバー通信を使用してください。
例外を投げた登録操作はログに記録して、その起動中は無効にします。
Webからクラス名・関数名・任意キーコード・コマンドを指定する仕組みはありません。

## ビルド

必要: **JDK 17、Node.js 22.18以上、npm**。Gradle Wrapper同梱。初回のみ依存ライブラリのダウンロードが必要です。

```sh
sh build.sh
# または ./gradlew build
# Windows
# gradlew.bat build
```

開発用の `runClient` も配布版と同じ隔離済みライブラリを使用します（`devShadowJar` → `prepareDevClient`）。
開発用クライアントの最大Javaヒープは2GBです。公式ランチャー側のメモリ設定には影響しません。
検証用に保存先を分ける場合はGradleへ `-PcraftlinkRunDirectory=/absolute/path` を渡せます（標準は `run/`）。

Web依存の `npm ci` → TypeScript検査 → Vite静的ビルド → Javaコンパイル → JUnitテスト →
依存ライブラリのパッケージ隔離 → Forge用の再難読化を実行します。
出力: `build/libs/craftlink-forge-1.20.1-0.1.0.jar`。
静的Web資産はJARの `web/` に同梱され、別Webサーバーは不要です。
NettyとZXingは専用パッケージへ移して同梱し、他MODのライブラリとの衝突を避けます。

```sh
./gradlew test         # セッション・タイムアウト・実HTTP/WebSocketのテスト
./gradlew runClient    # 開発用Minecraft（公式アカウントの認証環境ではありません）
npm --prefix web run build
npm --prefix web run dev # UI開発用。MODの接続はJAR内Web資産を使用
```

Javaコンパイルのみは `./gradlew compileJava`。Webを編集した場合は `build` でJARへ反映します。
GitHub Actionsでもビルドし、配布用JARをArtifactに保存します。

## シェルから起動（通常 / Wi-Fi不要のUSB）

ビルドは `sh build.sh`、開発用Minecraftの起動は次の2通りです。

```sh
sh run.sh       # 通常起動：Wi-Fiまたは有線LANで接続
sh run-usb.sh   # Android USB起動：Wi-Fi不要
```

どちらも必要なWeb・JavaコードをコンパイルしてからForgeの `runClient` を起動します。
**開発用クライアント** のため、公式ランチャーのログイン済みアカウントや既存プロファイルでの起動を代替するものではありません。
通常プレイ用のインスタンスではビルドしたJARを `mods` に導入してください。

USB用はAndroidのUSBデバッグとPCのADBが必要です。接続済みのUSB端末を確認し、ADB転送を設定した後、
この起動に限ってポート8765・待ち受け127.0.0.1・QR用ホスト127.0.0.1を使用します。
既存のForge設定ファイルには書き込みません。起動後は **F8 → 接続を開始 → QR読み取り → PCで承認** してください。
サーバーはスクリプト実行だけでは自動開始しません。

```sh
sh run.sh usb                   # run-usb.sh と同じ
sh run-usb.sh --port 9876        # ADBとMODに同じポートを指定
sh run.sh lan --port 9876        # 通常接続でポートを指定
```

USBスクリプトが新規作成した転送は、Minecraftの終了や起動失敗時に解除します。
元から同じ宛先へ設定されていた転送は再利用して残し、別の宛先への転送は上書きせずエラーにします。
iPhoneはADB非対応なので、このUSB起動スクリプトの対象外です。上記のUSBインターネット共有手順を使用してください。

## 設計

- `CraftLink.java`: Forgeクライアント初期化、F8登録、クライアントtick。
- `gui/LinkScreen.java`: 起動・停止・承認・切断・URLコピー・QR再発行・ユーザー名表示。
- `gui/ConnectionQr.java`: 専用WebリンクからローカルでQRを生成。
- `network/LinkServer.java`: NettyのHTTP / WebSocket、非同期起動・停止。
- `network/NetworkAddresses.java`: 有線・USB・VPNを含む接続先候補の列挙。
- `security/Session.java`: 256bitトークン、30分のセッション期限。
- `input/RemoteState.java`: サイズを制限した最新入力のメールボックス。
- `input/InputBridge.java`: Minecraftメインスレッド上の独立したリモート操作処理。
- `input/RemoteInput.java`: PC側Inputを保持したままスマホの移動意図を合成する専用Input。
- `input/RemoteButtons.java`: PC側と分離した押下状態・押下エッジ。
- `mixin/`: 通常の攻撃・使用ルーチンの呼び出し、長押し・ダッシュ意図の統合。
- `config/ConnectionSettings.java`: 通常・USB起動プロファイルの一時設定。
- `config/LinkConfig.java`: `config/craftlink-client.toml` の `port`（標準8765）。変更後は停止・再開始。
- `web/src/`: Pointer Eventsのマルチタッチ、30Hzの状態送信、ハートビート、再接続。

ネットワーク側からMinecraftの状態を変更しません。入力キューを無制限に積まず、視点差分も上限を設けます。
スマホは **CraftLink独自の入力ソース** として動作します。Minecraftの `KeyMapping.setDown` や `KeyMapping.click` を使った
キーボード・マウスの疑似押下は行いません。F8のGUIショートカットだけは通常のキー登録を使用します。
移動は専用 `RemoteInput` でPC側Inputを読み取り合成します。元のPC側Inputには書き込まないため、
スマホを離す・切断することでPCの移動・ジャンプ・スニークを解除することはありません。
同方向を同時に押しても速度を加算せず、逆方向は相殺します。Minecraftの減速係数を適用し、アイテム使用中の減速は通常のプレイヤー処理が行います。
攻撃・使用はMinecraftの通常のアクションルーチンを直接呼び出します。独自に速度・リーチ・ダメージを計算したり、位置を移動させたりしません。
Mixinでスマホの長押し意図を統合するため、キー状態を変えずに継続掘削・食事・弓などの継続使用に対応します。
ダッシュもPCのキー状態を変えずに意図を統合し、空腹・衝突・姿勢などの開始・停止判定はMinecraft側が行います。
インベントリは対応する画面・サーバー制御インベントリのAPIを直接使用します。
単発操作は押下の立ち上がり時のみ実行します。短いタップも状態変化時に即送信します。

## 接続と安全処理

- 起動時のサーバーは停止。明示的な開始で新しいセッションを発行。
- URLのフラグメントに一時トークンを格納。HTTP要求のパスやRefererには送信しません。
- WebSocketでトークンを確認後、PC側の承認が必要。同時に1台だけ受け付けます。
- 同一Origin確認、メッセージ長・頻度・操作名・数値範囲の検証を行います。
- 切断では入力を解除。入力通信が750ms途絶えた場合も、次のクライアントtickで解除。
- WebSocketの受信停止は5秒で切断。1秒周期のpingで往復遅延を表示。
- 一時的な通信切断時は2秒後に再接続し、PCで再承認が必要。
- 明示的な切断では自動再接続を停止。再開にはページ再読み込みが必要です。
- セッションは開始から30分で期限切れ。「QR再発行」、または「停止」→「接続を開始」でQRを更新してください。
- 終了時はshutdown hookで通信停止。任意キー入力、OSコマンド、ファイル操作用の通信APIはありません。

**LANのHTTP / WSは暗号化されません。信頼できるLANで使用してください。** HTTPポートを直接インターネット公開せず、遠隔接続には明示的にHTTPS中継を設定してください。
QRとURLは他人に見せないでください。読み取り可能な人はPCに承認要求を送れます。
PCのIPv4プライベートアドレスを自動列挙します。有線LAN・Wi-Fi・USBテザリング・仮想VPNの候補を、
F8画面下の「接続先」ボタンで切り替えるとQRとURLも切り替わります。トークンは同じセッション内で維持します。
`127.0.0.1` はAndroid USB転送用です。通常のWi-Fi接続時にはPCのLANアドレスを選択してください。
任意の到達可能なIPv4/DNSホストは設定ファイルの `advertisedHost` で先頭候補にできます。
`bindAddress` は待ち受け先で、標準は `0.0.0.0`（全IPv4インターフェース）、Android USB専用なら `127.0.0.1` にできます。
接続先の選択や設定だけでネットワーク経路が作られるわけではありません。

## iOS / Android と既知の制限

- iOS Safari / Android Chromeを想定したPointer Events実装です。実機・各OS版での検証は別途必要です。
- LANではHTTP / WS、HTTPS中継ではHTTPS / WSSを選び、混在コンテンツ通信を避けます。
- SafariのカメラでQRを読み取ります。Webページ内のカメラ、センサー、Pointer LockなどHTTPS必須のAPIを使用しません。
- iOSの全画面表示は端末・Safariの対応状況次第です。非対応なら通常表示のまま操作できます。
- PWAのService Worker、オフラインインストールは未実装です。LANのHTTPでは一般に利用できません。HTTPS中継でもPWA機能自体は未実装です。
- ゲストWi-Fiの端末間隔離、VPN、ファイアウォールで接続できない場合があります。ローカルネットワーク許可を求められた場合は許可してください。
- JPEG映像配信には帯域とGPU読み戻しの負荷がかかります。シェーダー・他MODとの組み合わせ、Safari/Android実機での映像遅延は未検証です。
- インベントリのアイテム移動、チャット文字入力、メニュー操作はPCを使用します。
- PC入力とスマホ入力は分離していますが、プレイヤー・視点・使用中アイテムは共有します。相反するアクションを同時に行うとMinecraftの通常の優先順位で処理されます。
- 操作処理にMixinを使用します。同じ攻撃・アイテム使用・ダッシュ処理を置き換える他MODとは、組み合わせごとの互換性確認が必要です。
- Java Editionの通常の移動・攻撃仕様です。マルチプレイヤーではサーバーの操作補助MODの利用規約を確認してください。
- 現時点の対応は **1.20.1 Forgeのみ**。Fabric・他Minecraft版の互換性は主張しません。通信・状態管理・Webは分離しており、
  追加ローダーでは初期化・GUI・InputBridgeを差し替える構成です。まず必須版の実機検証を優先します。
